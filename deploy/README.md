# Разворачивание CRM на боевом сервере

Инструкция для сервера с Docker и Docker Compose (Linux). Предполагается, что
домен (например, `crm.ava-solution.kz`) уже направлен на IP-адрес сервера
(A-запись в DNS) — без этого Let's Encrypt не сможет выдать сертификат.

Все команды выполняются из корня проекта на сервере.

Везде ниже используется `-p ava-crm-prod` — имя проекта Docker Compose.
Это важно: без него боевой запуск (`docker-compose.prod.yml`) и обычная
разработка (`docker-compose.yml`) на одной машине в одной папке создали бы
контейнеры и тома с одинаковыми именами и мешали бы друг другу. Если боевой
сервер отдельный и на нём никогда не запускается обычный `docker-compose.yml`,
флаг `-p` можно не писать — но лучше выработать привычку указывать его всегда.

## Шаг 1. Подготовить .env

```
cp deploy/prod.env.example .env
```

Откройте `.env` и замените все значения-примеры: домен, пароли, `JWT_SECRET`
(любая длинная случайная строка), почту для Let's Encrypt. Пока сертификата
нет, `NGINX_MODE` должен остаться `acme`.

## Шаг 2. Первый запуск и получение сертификата

```
docker compose -p ava-crm-prod -f docker-compose.prod.yml up -d --build postgres backend frontend
```

На этом шаге nginx (сервис `frontend`) поднимается в режиме `acme` — отдаёт
заглушку "CRM готовится к первому запуску" и умеет обслуживать проверку от
Let's Encrypt, но ещё без HTTPS. Backend сам применяет миграции базы при
старте — ничего отдельно накатывать не нужно.

Теперь выпустите сертификат (подставьте ваш домен и почту из `.env`):

```
docker compose -p ava-crm-prod -f docker-compose.prod.yml run --rm certbot \
  certonly --webroot -w /var/www/certbot \
  -d ВАШ_ДОМЕН --email ВАША_ПОЧТА --agree-tos --no-eff-email
```

Если команда завершилась без ошибок — сертификат лежит в томе `certbot_certs`.

## Шаг 3. Включить HTTPS

В `.env` поменяйте:

```
NGINX_MODE=tls
```

И пересоздайте frontend, чтобы он подхватил новый режим:

```
docker compose -p ava-crm-prod -f docker-compose.prod.yml up -d frontend
```

Запустите фоновое продление сертификата (само не поднимается вместе с
основными сервисами, чтобы не мешать первому выпуску сертификата):

```
docker compose -p ava-crm-prod -f docker-compose.prod.yml up -d certbot
```

Сертификат Let's Encrypt действует 90 дней, контейнер `certbot` проверяет
каждые 12 часов и продлевает заранее — вручную ничего делать не нужно, кроме
как проверять раз в пару месяцев, что контейнер `certbot` живой
(`docker compose -p ava-crm-prod -f docker-compose.prod.yml ps`).

Откройте `https://ВАШ_ДОМЕН` — должен открыться экран входа CRM.

## Шаг 4. Первый администратор (один раз)

Если в `.env` заданы `ADMIN_SEED_EMAIL`/`ADMIN_SEED_PASSWORD`, создайте
первого администратора и справочники (роли, отделы, юрлица):

```
docker compose -p ava-crm-prod -f docker-compose.prod.yml --profile seed run --rm backend-seed
```

Команда безопасна для повторного запуска — уже существующие записи не
дублируются.

## Обновление после изменений в коде

```
git pull
docker compose -p ava-crm-prod -f docker-compose.prod.yml up -d --build backend frontend
```

Миграции базы данных применяются автоматически при старте backend. Если
миграция не применится, контейнер backend завершится с ошибкой и не запустит
сервер — старая версия в это время уже остановлена, поэтому перед
обновлением на боевом сервере стоит сначала снять резервную копию базы
(шаг ниже).

## Резервная копия

Данные, которые нужно бэкапить: том `postgres_data` (сама база) и том
`uploads_data` (вложения, шаблоны документов). Пример снятия дампа базы:

```
docker compose -p ava-crm-prod -f docker-compose.prod.yml exec postgres \
  pg_dump -U ВАШ_POSTGRES_USER ВАША_POSTGRES_DB > backup-$(date +%Y%m%d).sql
```

## Режимы NGINX_MODE

- `acme` — только заглушка и приём проверки от Let's Encrypt, без HTTPS.
  Нужен один раз перед самым первым выпуском сертификата.
- `http` — обычная работа без HTTPS. Только для теста на сервере без домена
  и сертификата, для реальной эксплуатации не годится (пароли и данные шли бы
  в открытом виде).
- `tls` — боевой режим: HTTPS с уже выпущенным сертификатом, HTTP
  перенаправляется на HTTPS. Используется постоянно после шага 3.
