# Handoff: редизайн AVA CRM

## Overview

Полный редизайн интерфейса AVA CRM — CRM для экспедиторской компании (Алматы, Казахстан). Прототип покрывает **все** маршруты приложения `myrimkhan-hue/AVA-CRM` (ветка `main`, каталог `frontend/src`): 21 маршрут, включая вложенные лейауты настроек, отчётов и мотивации.

Задача редизайна: заменить дефолтный вид Ant Design на собственную визуальную систему — светлая «мягкая» оболочка со скруглёнными панелями, раскрывающийся по наведению сайдбар, тёмная тема, ролевая видимость разделов.

## About the Design Files

Файлы в этом бандле — **дизайн-референс, сделанный на HTML**. Это прототип, показывающий задуманный вид и поведение, а **не production-код для копирования**.

Задача: **воспроизвести эти макеты в существующем окружении целевого кодовой базы** — React 18 + TypeScript + Ant Design + react-router-dom, как в `frontend/`, используя её собственные паттерны, компоненты и библиотеки. Разметку из HTML переносить не нужно — нужно перенести визуальные решения, размеры, цвета, типографику и поведение.

Практически это значит: настроить тему Ant Design (`ConfigProvider` + `theme.token`/`components`) под токены ниже, а не переписывать компоненты с нуля. Там, где Ant Design не даёт нужного вида (раскрывающийся сайдбар, канбан сделок, кассовый календарь, карточки перевозок вместо `<Table>`), — верстать своими компонентами.

**Как открыть прототип:** откройте `AVA CRM soft.dc.html` в браузере. `support.js` и `assets/ava-logo.svg` должны лежать рядом — это рантайм прототипа и логотип. Навигация внутри прототипа работает: сайдбар, вкладки, кнопки переходов.

## Fidelity

**High-fidelity.** Все цвета, размеры шрифтов, отступы, радиусы и тени — окончательные, приведены ниже точными значениями. Копия должна быть попиксельно близкой, но собранной на компонентах кодовой базы.

Исключение: данные в прототипе — правдоподобные, но выдуманные (номера перевозок AVA-24xx, контрагенты, суммы). Брать их в код не нужно, они только показывают ожидаемый объём и формат содержимого.

### Отступы и сетка

- Внешний отступ приложения: `padding: 14px`, `gap: 14px` между сайдбаром и основной областью
- Сайдбар: `76px` свёрнутый → `246px` развёрнутый, `transition: width .2s cubic-bezier(.4,0,.2,1)`
- Пункт сайдбара: высота `42px`, `padding: 0 9px`, `gap: 12px`, между пунктами `gap: 6px`, контейнер `padding: 0 16px`
- Шапка: `padding: 13px 20px`, высота ~60px
- Панель-карточка: `padding: 22px 24px`; узкая (правая колонка) — `20px 22px`; KPI — `19px 21px`
- Между панелями: `gap: 14px`; между карточками списка перевозок: `gap: 10px`; между карточками канбана: `gap: 9px`
- Двухколоночный экран: `grid-template-columns: minmax(0,1fr) 336px`
- Дашборд, верхний ряд: `grid-template-columns: minmax(0,1.5fr) minmax(0,1fr)`; нижний: `minmax(0,1fr) minmax(0,1.4fr)`

- Канбан: `repeat(5, minmax(214px,1fr))`, `gap: 12px`
- Строка таблицы: `padding: 13px 0`, разделитель `border-top: 1px solid var(--line2)`
- Таблицы в панели: контейнер `padding: 8px 22px 14px`, внутри `overflow-x: auto` + `min-width` (900–1120px в зависимости от числа колонок)

## Interactions & Behavior

- **Раскрытие сайдбара**: `mouseenter` → 246px, `mouseleave` → 76px. Переход `width .2s cubic-bezier(.4,0,.2,1)`, тень `.2s`. Подписи, бейджи и кнопка выхода переключаются `display: none/block`. В свёрнутом состоянии у пунктов остаётся `title` для нативной подсказки. **На тач-устройствах** hover не работает — в реальном приложении нужна кнопка-гамбургер или постоянно развёрнутое меню (в коде уже есть `Drawer` для узких экранов, его и использовать).
- **Переключение темы**: кнопка в шапке меняет `data-theme` на корневом элементе. Иконка — луна в светлой теме, солнце в тёмной, `title` подсказывает, куда переключит. Все цвета через переменные, поэтому смена мгновенная и без перерисовки макета. В приложении тему стоит хранить в `localStorage` и учитывать `prefers-color-scheme` при первом входе.
- **Уведомления**: клик по колокольчику открывает/закрывает поповер. Клик по записи ведёт на связанный экран. В приложении добавить закрытие по клику вне и по Escape.
- **Ролевая видимость** (перенесено из `App.tsx`): недоступные роли разделы скрываются из сайдбара, а попытка попасть на них перебрасывает на «Перевозки».

  | Роль | Скрыто |
  | --- | --- |
  | Логист | Сделки, Лиды, Счета, Документы, Расходы, Пользователи, Настройки |
  | Менеджер | Документы, Расходы, Пользователи, Настройки |
  | Финансист | Лиды, Пользователи, Настройки |
  | Руководитель отдела | Расходы, Пользователи, Настройки |
  | Директор | — |

  Источники в коде: `LEAD_ROLES`, `INVOICE_ROLES`, `OPERATING_EXPENSE_ROLES`, `DOCUMENT_ACCESS_ROLES`, а также `DealsRoute` / `DealDetailRoute` / `LeadsRoute` / `InvoicesRoute` / `DocumentsRoute` / `OperatingExpensesRoute`. **Роли «Пользователи» и «Настройки» в прототипе ограничены директором — в коде такого ограничения нет**, это предложение дизайна; согласуйте перед реализацией.
- **Сокрытие маржи**: маржа и рентабельность видны ролям Директор, Финансист, Руководитель отдела. Остальным — в списке перевозок подпись «маржа скрыта», в карточке — «Маржа скрыта для роли «{роль}»», KPI-карточка «Маржа» на дашборде не выводится. Это дизайнерское предложение, в коде такой логики нет.
- **Ховеры**: строка таблицы → `--rowhover`; карточка перевозки → тень `0 4px 20px var(--sh10)`; карточка канбана → `0 4px 16px var(--sh10)`; вторичная кнопка → `--hover`; primary → `#C10F0A`; тёмная кнопка → `--ink-h`; пункт сайдбара → `transition: background .14s`.
- **Горизонтальный скролл таблиц**: у широких таблиц контейнер `overflow-x: auto` + внутренний `min-width`, чтобы шапка и строки скроллились вместе, а панель не растягивала страницу.
- **Не реализовано в прототипе** (нужно доделать в приложении): реальная сортировка и фильтрация, пагинация (кроме визуальной), состояния загрузки и пустых списков, валидация формы новой перевозки, шаги 2 и 3 этой формы, drag-and-drop в канбане.

## State Management

Прототип держит всё в одном компоненте. В приложении это ляжет на роутер и серверное состояние, но список нужных состояний такой:

| Состояние | Значения | Назначение |
| --- | --- | --- |
| `screen` | ключ экрана | в приложении — маршрут |
| `theme` | `light` / `dark` | тема, хранить в `localStorage` |
| `open` | boolean | развёрнут ли сайдбар |
| `notif` | boolean | открыт ли поповер уведомлений |
| `rtab` | `debit` / `credit` | вкладка отчётов (в коде — маршрут) |
| `mtab` | `my` / `summary` | вкладка мотивации (в коде — маршрут) |
| `stab` | 7 значений | вкладка настроек (в коде — маршрут) |
| `ltab` | `all` / `my` / `site` | фильтр лидов |
| `dtab` | `all` / `contract` / `request` / `invoice` / `act` | фильтр документов |
| `etab` | `all` / `unpaid` / `paid` | фильтр расходов |

Роль приходит из `AuthContext` (`user.roles`) — в прототипе это параметр для демонстрации.

Данные: перевозки, сделки, лиды, контрагенты, счета, заявки, документы, расходы, движения по календарю, отчёты старения, показатели мотивации, пользователи, справочники настроек. Всё — с сервера, в прототипе захардкожено.
